# 发布检查：私有试点到生产

第一阶段是可运行的安全工程基础，不等于已通过生产上线审核。

## 每次发布

- [ ] lint、类型检查、测试、依赖审计和 Linux/macOS CI 均通过。
- [ ] 容器构建及真实 HTTP 冒烟测试通过。
- [ ] 人工检查策略变更、保护边界以及引入的依赖；没有秘密或真实数据进入提交。
- [ ] 为配置分配新的 policy version，并记录服务版本与配置摘要。
- [ ] 固定基础镜像 digest，扫描镜像并保留构建产物和依赖清单。
- [ ] 选择可回滚的不可变镜像；回滚时验证旧版本仍兼容当前策略和凭据配置。

## 首次上线前

- [ ] 明确数据所有者、使用者和允许接收发布结果的客户端。
- [ ] Agent 与网关使用不同的系统身份/容器；Agent 无法读取网关的文件、环境或凭据。
- [ ] 网关只读挂载最小数据范围；Agent 不能写入源目录及其祖先。
- [ ] 在可信边界外使用 TLS，关闭请求体、认证头和原始 URL 的代理日志。
- [ ] 入口设置速率、连接、请求头大小和超时限制，禁止直连绕过入口。
- [ ] 设置网络出口规则；当前文件服务不需要访问外部网络。
- [ ] 从部署秘密管理系统注入不同主体的随机 token；完成吊销与轮换演练。当前轮换需要重启。
- [ ] 审计日志由受控收集端保存，设定访问权限、保留时间及异常告警；不自动收集堆栈局部变量。
- [ ] 对 `403/422/5xx`、审计故障及拒绝量异常配置监控。
- [ ] 完成独立安全评审和真实部署中的旁路验证，并约定事件响应负责人。
- [ ] 完成数据处理、许可和合同评估；不要使用未经验证的合规或“绝不泄漏”表述。

## 扩展阶段再引入

企业身份集成、动态策略管理、多租户控制面、更多 API 协议适配、隔离计算、细粒度发布策略和托管管理平台。每项扩展都需要更新威胁模型。
